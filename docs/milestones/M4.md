# M4 — reuse setup między portami

Status: **ACTIVE**, po zamknięciu oceny M3 w EXP86–90.
Wyniki i ograniczenia poprzedniego etapu: [prefetch](../basis-prefetch.md).
Bez globalnej promocji prefetchu; zachować FP64 reference oraz FP32direct opt-in.

## Kolejność

1. Audyt EXP91 wykazał osobny setup/faktoryzację per port. W obrębie częstotliwości
   zmienia się RHS, a terminacje pozostają. Coax tiny/medium reuse PASS; pełny
   eksperyment obu portów anteny nie jest jeszcze zakwalifikowany.
2. Dodać minimalne liczniki tylko tam, gdzie istniejące logi nie rozstrzygają.
   Najpierw coax-tiny/oba porty/ta sama częstotliwość, potem W.2 i uzasadniony W.3.
3. Jeśli setup powtarza się przy identycznych A/P, prototyp reuse z jawnym
   unieważnianiem po zmianie operatora/terminacji. Pełny czas obu RHS i frozen K.
   Jeśli reuse już istnieje, udokumentować liczbę faktoryzacji oraz odrzucić duplikat.
4. Symbolic reuse między częstotliwościami i warm start badać osobno tylko przy
   wykazanym koszcie; nie przenosić numerycznych faktorów między różnymi A(f).

5. EXP92 pełny control obu portów anteny FAIL/OOM podczas P2. Postprocessing P1
   pozostawił około16,5GB dodatkowych alokacji managed. EXP93 tiny release/rebuild
   energii PASS, zmierzony drop36,86MB; pełnego efektu nie ekstrapolować. Następnie
   medium pair i pełna antena, ta sama polityka pamięci/starty w control/reuse.

Zamknięcie według M4.1–M4.4 w MILESTONES.md. Medium, cache, limity/no swap,
tylko RAM/VRAM; ta sama Luna uruchamia wyłącznie przygotowane argv.
