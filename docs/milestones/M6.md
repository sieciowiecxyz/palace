# M6 — kernele CUDA, Tensor Cores i sweepy

Status: **ACTIVE**, po zakończonej ocenie M5/EXP104,2026-10-21.
M6.1–M6.6 w [MILESTONES](../../MILESTONES.md), osobno [sweepy](sweeps.md).
Wszystkie bramki jakości/pamięci pozostają; bez płatnego compute i Rust/GUI/CAD.

## Zmierzony punkt wyjścia

Native complex scaled FP32 LU +2 FP64 CUDA korekcje, direct FP32 GMRES storage,
oryginalny outer operator/residuum FP64. W.3 3,50GHz/P2:273,843s,35iter,
cgroup45,376GB/managed40,963GB; fullgrade K i W.2 trzyfreq/oba porty PASS.
Jedna para, nie mediana ani W.4/W.5. FP64 fallback zachowany. Raporty:
[mixed coarse](mixed-coarse-plan.md), [profil](../mixed-coarse-profile.md).

Pełne exclusive timery: Setup48,390s, coarse32,038s, pozostały PC95,123s,
LinearSolve poza tym23,014s; native Total271,522s. Usunięcie wszystkich
coarse apply mogłoby dać najwyżej1,134× całego runu. PC poza coarse to35%
Total, ale nie przypisujemy tej całości jednemu kernelowi.

Późne dwie iteracje30:2:10,530s, PC8,704s/coarse2,279s,186,635GB UVM.
Największe wybrane kernele: Hcurl1,914s/96calls, MAGMA interp0,982s/144calls,
MAGMA deriv0,876s/160calls, HdivMass0,578s/40calls. CUDA elapsed może zawierać
UVM stalle; to nie sam koszt FLOP i nie rozkład całej symulacji.

## Źródła i pierwsza decyzja M6.1

Read-only kopia backendu MAGMA z zatrzymanego stałego buildera, bez jego
uruchamiania i przebudowy. Actual `ceed-magma-basis.c` SHA
0c41d35fde4470965b7b2beb6d1801aef526fea1c4c53e32f62bce7cdd1357ff
potwierdzono z [libCEED cbd49027b0ae891f0c8efd9d9cf05bc82385a388](https://github.com/CEED/libCEED/blob/cbd49027b0ae891f0c8efd9d9cf05bc82385a388/backends/magma/ceed-magma-basis.c).
Istniejący stos/pin pozostaje; libCEED BSD-2-Clause (pin/licencja w researchu M0).

`CeedBasisApplyNonTensorCore_Magma`: P=liczba nodes bazy, Q=liczba quadrature
points, N=num_elem*num_comp. Dla P,Q≤40 używa własnych RTC interp/deriv kernels;
większe bazy idą przez `magma_gemm_nontensor`. Profilowane nazwy wskazują
aktywność ścieżki custom, więc samo ustawienie cuBLAS math mode nie przyspieszy
tych wywołań. `CEED_EVAL_CURL/DIV` również obsługuje ta ścieżka — nazwa
"deriv" nie dowodzi H1 gradientu. Transpose i ApplyAdd mają inne wymagania sumowania.

M6.1 **jeszcze niezaliczone**: rzeczywiste P/Q/N/q_comp dla wszystkich aktywnych
poziomów/kształtów oraz wektorów nie zostały zmierzone. Nie zgadywać Q z samego
Order2 ani "33" w nazwie QFunction. Receipt: artifacts/m6-kernel-selection-20261021.json.

## Kolejność dalszej pracy

1. Mały opt-in audyt baz/operatorów (P,Q,N,q_comp,transpose/add, bytes/calls),
   najpierw coax-tiny. Jeden cached build lub osobny cached backend object,
   bez rebuilda dependencies. Zmierzyć actual wymiary W.3 tylko gdy potrzebne,
   nie zaczynać od pełnego wieloczęstotliwościowego solve.
2. Dopiero z wymiarami: ocenić cuBLASLt batching/TF32, istniejący MAGMA backend,
   realną arytmetykę/current kernels i optymalizację ruchu/fuzji. CUTLASS tylko
   przy konkretnej brakującej funkcji. Biblioteki i mały prototyp przed integracją.
3. Known-vector/basis action FP64 reference, FP32 i TF32, transpose/ApplyAdd,
   curl/div, nietypowe batch sizes, wiele składowych i perturbation detector.
   Liczyć packing/scatter/workspace i całe apply; test sekundowy wRAM/VRAM.
4. Oddzielić optymalizację PC od oryginalnego A. Globalna zmiana CeedScalar albo
   backendu dla A i kontrolnego Ax−b mogłaby ukryć błąd; zachować niezależny
   oryginalny FP64 residual i frozen K. Żadnej deklaracji outerFP64 po globalnej
   podmianie jego operatorów. Zmienny PC wymaga świadomej oceny FGMRES/pamięci.
5. Actual TC potwierdzić instrukcjami/licznikami; TF32 nie zmniejsza storage
   FP32. BF16/FP16 to osobna hipoteza. Jeśli TC/przeliczanie nie daje netzysku,
   ocenić fuzję/batching/strumieniowanie istniejących operatorów bez TC.
6. W.1→W.2→W.3, K i koszt całego runu przed promocją. Dopiero potem M6.6
   sweep3,3–3,9GHz/oba porty z held-out points, oryginalnym residual i całym
   kosztem przygotowania. Nie przenosić LU między różnymi A(f).

M7 nadal wymaga W.4/W.5, trzech powtórzeń/mediany, dodatkowej geometrii i pakietu.
Brak wymuszenia TC ani zysku kosztem jakości. Defaulty bez zmian.
